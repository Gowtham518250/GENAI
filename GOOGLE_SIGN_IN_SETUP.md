# Google sign-in setup

The Flutter app and the Retail Mind API must use the same Google **Web application OAuth client ID**. Do not use the Android OAuth client ID for `GOOGLE_OAUTH_CLIENT_ID`.

## 1. Configure Google/Firebase

1. In Firebase Console, select the Firebase project used by Retail Mind and confirm the Android app package name is `com.retailmind.app`.
2. Add the SHA-1 and SHA-256 fingerprints for the debug keystore and the release/upload keystore in the Firebase Android app settings.
3. Enable Google as a sign-in provider if Firebase Authentication is also used by the project.
4. Create or confirm a Google OAuth **Web application** client ID.
5. Download the updated `google-services.json` for the Android app and replace `android/app/google-services.json`. It must be the real file generated by Firebase Console; placeholder IDs do not work.

Do not commit service-account private keys or other server secrets to Git.

## 2. Build/run Flutter with the Web OAuth client ID

PowerShell example:

```powershell
flutter run --dart-define=GOOGLE_OAUTH_CLIENT_ID=YOUR_WEB_CLIENT_ID
```

Production APK example:

```powershell
flutter build apk --dart-define=GOOGLE_OAUTH_CLIENT_ID=YOUR_WEB_CLIENT_ID --dart-define=API_BASE_URL=https://retail-mind-vkbp.onrender.com
```

Replace `YOUR_WEB_CLIENT_ID` locally with the value ending in `.apps.googleusercontent.com`. Do not include angle brackets in the command.

## 3. Configure the backend

Set `GOOGLE_OAUTH_CLIENT_ID` in the backend hosting environment to the **same Web application client ID**. The `/auth/google` endpoint verifies the ID token's signature, expiry, issuer and audience before issuing a Retail Mind API session.

Redeploy the backend after adding the environment variable. Never accept the email/name sent by the app as proof of identity; they are derived from the verified Google token on the server.

## 4. Verify

Test on a physical Android device using both debug and release signing configurations. Confirm that existing accounts log in, a first-time Google account gets an owner profile, a disabled account is rejected, and a missing/mismatched OAuth client ID shows an actionable error rather than pretending login succeeded.
